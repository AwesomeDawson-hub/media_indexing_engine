## Architect Decision

`P12-010` should be implemented as a **narrow bounded-concurrency sync-throughput slice that overlaps only admitted connector analysis tasks while preserving zero-transient connector ingestion, centralized quota admission, per-item failure isolation, and accurate sync-run completion semantics**.

This plan does not reopen Phase 9 architecture. It formalizes the smallest safe first implementation of the already approved `ARCH-005` direction.

Locked architectural position:

- ARCH-002 source-of-truth rules remain unchanged
- ADR-031 remains authoritative for why inline sync-flow analysis was used in the first zero-transient slice
- the long-term retry contract remains source re-fetch rather than hidden app-retained original replay
- connector-ingested items remain `storage_mode='reference'`
- this workstream is future planning only and does not displace `P12-009` as the active workstream

## Objective

Increase connector sync throughput by reintroducing a small bounded amount of concurrency only after items have been admitted into connector analysis.

The target outcome is:

- one sync coordinator remains responsible for listing, idempotency checks, and admission
- a small bounded number of connector analysis tasks may run concurrently
- quota is still reserved explicitly before each admitted task starts
- no unbounded queue of downloaded bytes accumulates waiting for analysis slots
- sync-run completion means all admitted tasks have settled
- quota exhaustion stops new admission immediately but does not abandon already admitted work

## Current Live Baseline

The current code is more serialized by design, not by accident.

Today `src/connectors/sync_service.py` does the following in order for each eligible remote object:

1. download object bytes
2. call `process_connector_import(...)`
3. reserve quota for the new item when analysis is enabled
4. persist `SourceObject` identity and link `OriginAssetRef`
5. `await analyze_connector_item(...)` inline before moving to the next object

Current analysis behavior in `src/analysis/processor.py`:

- `analyze_connector_item()` is documented as synchronous single-attempt analysis for connector-ingested reference-mode items
- it uses caller-provided bytes directly
- it does not read from `storage_path`
- it does not retry inside the sync path
- Drive rename and metadata embed currently run inside the same analysis task
- analysis work is already subject to the processor semaphore via `_analysis_semaphore`, but sync orchestration remains effectively serialized because `sync_service` awaits each analysis task inline

This baseline must be described honestly because `P12-010` changes sync orchestration behavior, not the Phase 9 storage contract.

## Scope

### In Scope

- keep one sync coordinator in `src/connectors/sync_service.py`
- add bounded concurrent execution only for admitted connector analysis tasks
- centralize admission behind explicit slot availability
- reserve quota before task spawn
- return structured terminal task outcomes to the coordinator
- delay sync-run finalization until all admitted tasks settle
- add only the aggregated sync-run accounting needed for correctness and operator trust
- preserve current mutation/write-back work inside the bounded task
- add focused tests and conservative rollout controls

### Explicit Non-Goals

- no new scheduler platform
- no distributed worker system
- no generalized retry architecture redesign
- no connector-health subsystem
- no UI monitoring redesign
- no provider-wide adaptive scheduling
- no pipeline-wide parallelization
- no reopening of hidden or transient retained-original behavior
- no move of Drive rename or metadata embed into a separate execution subsystem

## Locked Decisions

## D1 — One sync coordinator only

The first slice keeps a single sync coordinator responsible for remote listing, idempotency checks, quota admission, task spawn, result aggregation, and final run status.

## D2 — One admission path only

Every admitted connector analysis task must be created through one coordinator-owned admission path. No secondary or background admission mechanism is allowed in this slice.

## D3 — Concurrency applies only after admission

Remote listing, idempotency checks, and source-object skip logic remain serial in the first slice. Concurrency starts only after an item has been admitted to analysis.

## D4 — Admission requires an available slot

The coordinator may admit a new analyzable item only when a bounded analysis slot is available.

## D5 — Quota must be reserved before task spawn

Quota reservation remains explicit and per-item. The coordinator must reserve quota before creating an in-flight analysis task.

## D6 — No unbounded downloaded-byte backlog

The coordinator must not accumulate an unbounded queue of downloaded bytes waiting for analysis workers. At most one coordinator-owned candidate item may be held while waiting to acquire an analysis slot.

## D7 — Admitted tasks must return structured terminal outcomes

The coordinator must receive a structured terminal result from each admitted task so sync-run aggregation reflects final analysis outcomes rather than only import/download success.

## D8 — SyncRun finalization waits for all admitted tasks

`SyncRun.status` and `completed_at` must not be written until all admitted tasks have settled.

## D9 — Quota exhaustion stops new admission immediately

Once quota reservation fails for a candidate item, the coordinator must stop admitting any new analysis work in that run.

## D10 — Already admitted tasks must drain before finalization

Quota stop, analysis failure, or enumeration completion must not bypass draining already admitted tasks before run finalization.

## D11 — Mutation/write-back stays inside the bounded task

Drive rename and Drive metadata embed remain inside the same bounded analysis task in `P12-010`. This slice does not create a second mutation worker boundary.

## D12 — Dedicated config setting controls rollout

The feature must use a dedicated connector-analysis concurrency setting. Effective first-slice allowed range is `1..3`. The initial rollout target is `2`. Moving to `3` is evidence-gated, not assumed.

## Detailed Step Plan

## Step 1: Introduce a coordinator-owned admitted-task result contract

### Objective

Give sync orchestration a reliable way to aggregate analysis outcomes without turning the coordinator into a broad scheduler.

### Required outcome

- define a small internal task-result shape for admitted connector analysis work
- include terminal outcome at minimum for success, failure, and quota-stop interaction context where needed
- ensure the coordinator can update `SyncRun` counters and summary text from task outcomes rather than relying on non-fatal log messages alone

### Constraints

- do not introduce a new persistent task table
- do not create a generalized worker abstraction for unrelated pipelines

## Step 2: Add a bounded in-flight analysis admission loop in `sync_service`

### Objective

Replace inline per-item awaiting with a slot-bound admitted-task model while keeping the overall coordinator serial.

### Required outcome

- listing remains serial
- per-object idempotency check remains serial
- import and source-identity persistence remain coordinator-owned
- after admission, analysis tasks may overlap only up to the configured bound
- the coordinator waits for slot availability before admitting additional analyzable items

### Constraints

- no whole-pipeline async rewrite
- no unbounded backlog of pending analysis tasks
- no prefetch queue detached from slot availability

## Step 3: Preserve deterministic quota-stop and drain behavior

### Objective

Keep quota behavior explicit and operator-trustworthy even when some analysis tasks are already in flight.

### Required outcome

- reserve quota before task spawn
- if quota reservation fails, stop admitting further items immediately
- keep already admitted tasks running
- do not finalize the run until all admitted tasks settle
- aggregate quota stop into `SyncRun` terminal status and summary text

### Constraints

- do not silently skip quota-stopped objects without recording the stop condition
- do not continue admitting new work after quota stop

## Step 4: Keep current reference-mode analysis and mutation behavior intact

### Objective

Improve throughput without changing the current analysis-input or write-back architecture.

### Required outcome

- `analyze_connector_item()` continues using caller-provided bytes
- no new `storage_path` dependency is introduced
- no retry loop is added to connector sync analysis
- Drive rename and metadata embed remain inside the same admitted task boundary

### Constraints

- do not reopen ADR-031 retry/storage decisions
- do not move mutation/write-back into a separate subsystem

## Step 5: Add focused tests and conservative config rollout support

### Objective

Make the slice safely reversible and verifiable before any later tuning work.

### Required outcome

- add dedicated connector-analysis concurrency config
- clamp effective values to `1..3`
- preserve `1` as the safe fallback behavior
- add focused tests for concurrency cap, drain, quota-stop, and bounded memory/backlog behavior

### Constraints

- do not broaden into provider-specific tuning in this slice
- do not assume `3` as the default rollout target

## Admission Model

The first slice uses a coordinator-owned slot-bound admission model.

Locked admission flow:

1. list one remote object at a time
2. perform current serial idempotency and exclusion checks
3. download bytes for the candidate object only when the object has passed those checks
4. import the candidate item through the current connector import path
5. reserve quota for that imported item before task spawn
6. persist `SourceObject` identity and `OriginAssetRef` linkage before task start, as the current contract requires
7. spawn an admitted analysis task only when a slot is available
8. keep a bounded set of in-flight admitted tasks
9. as tasks settle, aggregate their outcomes and free slots for further admission

The coordinator remains the only authority for admission and final run aggregation.

## Completion and Aggregation Rules

`P12-010` changes sync completion semantics from effectively inline completion to admitted-work completion.

Locked rules:

- sync enumeration finishing is not sufficient for run completion
- sync run completes only after all admitted tasks reach terminal state
- `completed_at` must be written only after the drain is complete
- aggregated counters must reflect admitted-task outcomes, not only import/download outcomes
- aggregated summary text may remain narrow and human-readable; this slice does not require a new detailed operator dashboard

Preferred aggregation shape for this slice:

- reuse existing `SyncRun` terminal states and counters where possible
- add only the minimum summary detail necessary to preserve operator trust when quota stop or analysis failures occur during concurrent execution

## Quota Rules

Quota behavior remains explicit and admission-bound.

Locked rules:

1. quota reservation occurs before analysis task spawn
2. quota reservation failure is an admission-stop event, not a background failure
3. once quota stop occurs, no further candidate item may be admitted in the same run
4. already admitted tasks continue to settlement
5. run finalization occurs only after those admitted tasks settle
6. run terminal state after quota stop remains `completed_with_errors`
7. run summary must state that sync stopped because monthly quota was exhausted

## Memory/Backlog Rules

The first slice must not trade serialized correctness for unbounded memory use.

Locked rules:

- no unbounded downloaded-bytes queue may be introduced
- slot availability gates admission
- the coordinator may hold only the current candidate item plus the bounded in-flight set
- a separate byte-budget scheduler is intentionally deferred

This slice treats slot-bound admission as the required first memory-safety boundary.

## Failure Handling Rules

Per-item failure isolation remains mandatory.

Locked rules:

- one admitted task failure must not abort already admitted peer tasks
- task failure must be aggregated into run-level failure accounting
- coordinator aggregation must distinguish analysis failure from quota stop
- this slice does not introduce a connector-health subsystem or new long-lived degraded-state taxonomy
- existing coarse `Source.connector_status` behavior may remain in place in the first slice

Narrow tightening applied in this plan:

- because concurrent execution would otherwise amplify ambiguity, `P12-010` must treat admitted task terminal outcomes as first-class sync accounting inputs rather than relying on best-effort warning logs alone

## Mutation/Write-Back Boundary

Drive rename and metadata embed remain inside `analyze_connector_item()` for `P12-010`.

Locked rules:

- the admitted task boundary includes analysis, indexing, Drive rename, and Drive metadata embed exactly as the current processor path does
- this slice does not split mutation into separate tasks
- any future mutation/write-back concurrency redesign requires a separate later architectural decision

## Configuration Contract

`P12-010` must introduce a dedicated connector-analysis concurrency setting rather than overloading the global processor semaphore setting.

Locked contract:

- dedicated config name should express connector sync analysis concurrency explicitly
- effective first-slice allowed range is `1..3`
- invalid or out-of-range values must fail closed into the bounded allowed range rather than permitting broad fanout
- value `1` must preserve the safe fallback behavior closest to the current inline baseline
- rollout target is `2`
- use of `3` requires observed stability evidence and explicit operator choice

The existing processor semaphore remains part of the downstream analysis safety envelope, but it is not sufficient by itself because the current sync loop is still serialized by inline awaiting.

## Validation

Validation for `P12-010` must prove throughput improvement did not weaken the Phase 9 safety model.

Minimum validation:

- focused automated tests for slot-bound admission and task drain behavior
- focused automated tests for quota-stop and aggregation behavior
- focused automated tests proving fallback value `1` preserves safe behavior
- focused automated tests proving no hidden-original or `storage_path` regression
- focused automated tests proving no unbounded downloaded-byte backlog behavior in the first slice
- manual or scripted validation with rollout target `2` against a small real or representative Drive source

## Required Tests

The following expectations are locked for `P12-010`:

1. worker cap is enforced
2. sync run does not complete before all admitted tasks finish
3. quota exhaustion stops further admission deterministically
4. already admitted tasks still finish after quota stop
5. analysis failure increments aggregated failure accounting
6. per-item failure isolation is preserved
7. no hidden-original or `storage_path` regression is introduced
8. no unbounded downloaded-byte backlog behavior is introduced by the first slice
9. configuration value `1` preserves safe fallback behavior
10. rollout target `2` works in focused or manual validation

## Auditor Focus

The Auditor should verify:

1. no drift against ARCH-002 or ADR-031
2. no hidden retained-original replay path or `storage_path` regression
3. concurrency is limited to admitted connector analysis tasks only
4. one sync coordinator and one admission path remain true
5. quota reservation still happens before task start

7. run finalization waits for all admitted tasks

## Rollout Notes

`P12-010` should be rolled out conservatively.

Locked rollout notes:

- keep this workstream future-only until separately promoted through governance
- when implemented, start with effective concurrency `2`
- preserve config fallback to `1` without code changes
- do not move to `3` automatically
- evidence required before moving to `3` includes acceptable memory behavior, acceptable Drive/provider throttling behavior, and acceptable mutation/write-back contention
